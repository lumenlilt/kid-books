## Context

使用者要一個瀏覽器可開的 **3D 書架**，給幼稚園到國小低年級的小孩：點一本書 → 書打開 → 教一個主題；
過程要有趣、有成就感；每完成一個主題有可收集的東西讓小孩想學更多。第一本書從「幼小銜接」選題。
成品要推上 **`lumenlilt.app` 當公開 open source 專案**，品質對齊商用兒童 App。

兩個已知現況會影響做法：
- `lumenlilt.app` 是一個 Cloudflare Worker＋靜態資產的站（正本在 `runway/site/`，Worker 依主機名分流 `lasts.lumenlilt.app`）；DoseKit 則是獨立專案綁 `evertend.lumenlilt.app`。GitHub 目前登入 `lumenlilt` 帳號。
- harness 的開案腳本 `new-project.sh` 遇到已存在目錄會拒絕，而 `kid-books/` 已存在但是空的。

## 產品設計（第一版範圍）

### 主畫面：房間 ＋ 書架
- 一間溫暖的小房間：一座書架（Kenney `bookcase`）、檯燈、地毯、盆栽、窗戶（窗外依裝置真實時間切換白天／黃昏／夜晚——這本身就是時鐘書的伏筆）。
- 書架一層 **6 格**：v1 放 **1 本真書**（時鐘）＋ **4 本鎖住的剪影書**（灰色、書脊「?」，點了會晃一下＋旁白「這本書還在寫，先把時鐘書讀完吧！」）＋ 1 格空位。**不做整面牆的書**——五歲小孩面對太多選擇會當機，稀缺＋好奇比豐富有效。
- 房間牆上與桌上有 **3 個裝飾空位**（虛線剪影）。讀完時鐘書 → 牆上出現一個**會走的咕咕鐘**（顯示真實時間，整點會叫）。
- 滑鼠移動／iPad 陀螺儀 → 鏡頭微幅視差；輕點檯燈會開關、輕點盆栽會晃——「什麼都可以摸」是給小孩的信號。
- HUD：左上「誰在玩」頭像、右上聲音開關與星星總數；**沒有文字選單**——不識字的小孩看得懂的只有圖示與聲音。
- 旁白角色：**一隻貓坐在書架頂上**（3D、紙雕風、程式幾何做的低多邊形貓；不夠可愛再用 Blender bpy 腳本重做）。閒置時擺尾、眨眼、偶爾伸懶腰；講話時嘴巴隨旁白開合；小孩答對時跳起來歡呼；點牠會喵一聲。牠是「聲音的臉」，不養、不餵。使用者選了場景裡的貓而不是 HUD 角色，工量約兩倍，理由是存在感。

### 點書 → 立體書打開（3D 段）
1. 書從書架**滑出**（Z 軸）並微微傾斜 → 2. **飛到閱讀位**（畫面中央，向鏡頭傾 25°）→ 3. 封面繞書脊翻開 → 4. **紙雕場景隨翻開角度立起來**（每個紙片的旋轉是翻開角度的函數，像真的立體書，而不是獨立播放的動畫）→ 5. 鏡頭微推 → DOM 控制層淡入。
- 關書反向播放；回到書架時鏡頭**先停在新出現的裝飾上**再回到書架（成就要被看見）。
- **貓跟著書走**：書飛到閱讀位時，貓從書架頂跳到翻開的書頁角落坐下（同一個 3D 場景，所以進到立體書頁面不用另外處理牠在哪）；關書時跳回書架頂。

### 時鐘書：舞台與頁面
舞台（3D 紙雕）：一座鐘樓（大鐘面是 3D 的、指針是獨立 mesh）、一間小房間剖面（床、餐桌、書包）、天空（太陽／月亮沿弧線走）、小孩自己的頭像紙片（做作息動作）。

**「控制器在 DOM，世界在 3D」**：小孩拖的是 DOM 裡一個很大的 SVG 時鐘（觸控目標 ≥ 64px、可無障礙）；鐘樓的 3D 鐘面、太陽月亮、頭像動作**每一幀鏡射**這個時間。轉指針 → 世界跟著變，是這本書最核心的因果迴圈。

**每一頁都「先玩再學」**：頁面打開先是自由玩（旁白邀請「轉轉看！」），互動 3 次或 8 秒後旁白才給任務。

| 頁 | 內容 | 活動元件 | 星星條件 |
|---|---|---|---|
| 0 | 開場：立體書立起來，旁白介紹鐘樓 | `intro` | 自動 |
| 1 | 轉轉看：自由拖指針，看世界變化 | `clock-free` | 互動 3 次 |
| 2 | 整點：只教短針指數字、長針指 12；「轉到 3 點」「7 點」「12 點」 | `clock-set` ×3 | 3 題完成（錯了不扣，第 2 次錯給提示、第 3 次示範） |
| 3 | 哪個是 8 點？三個時鐘選一個 | `clock-choose` ×3 | 同上 |
| 4 | 半點：長針指 6、短針在兩數中間；「轉到 3 點半」×2、選出半點 ×2 | `clock-set`／`clock-choose` | 同上 |
| 5 | 小明的一天：作息場景（7 點起床、8 點上學、12 點午餐、3 點半點心、9 點睡覺）拖時鐘卡到對的場景 | `match-time-scene` | 5 組配對 |
| 6 | 現在幾點？大鐘顯示裝置真實時間；旁白：「去找爸爸媽媽，一起看看家裡的時鐘現在幾點！」 | `bridge` | 點「我看過了」 |
| 7 | 頒獎：星星飛進徽章、咕咕鐘飛回房間牆上 | `ceremony` | — |

**沒有失敗狀態**、沒有計時壓力、沒有連續登入之類的罪惡感機制。

### 成就感的四層回饋
1. 每次觸碰：音效＋彈性縮放（Kenney Interface Sounds，CC0）。
2. 每頁：星星爆開、飛到 HUD 計數。
3. 每本書：頒獎頁＋書脊上多一條金色書籤（回書架看得到）。
4. 房間：新裝飾出現，鏡頭先帶去看。

### DOM 與 WebGL 對位（選定做法：固定閱讀姿態＋每次 layout 投影一次）
翻開後鏡頭停在確定的「閱讀姿態」；`app/layout.ts` 是**唯一的 resize 入口**：讀 `visualViewport`（iOS 旋轉後 `innerWidth` 會暫時是舊值）→ 重算閱讀姿態（讓書頁填滿 ~88% 高度，純函式 `solveReadingPose`）→ 把攤開書的包圍盒八個角 `project()` **一次**成 CSS 像素寫進 CSS 變數，DOM 容器貼上去；控制元件用百分比／容器單位排在容器內。觸發：resize、`visualViewport.resize`、orientationchange → rAF×2＋120 ms debounce。
- 為什麼不每幀投影：子像素抖動、每幀 layout 成本、iOS 旋轉當幀數值錯誤會閃。為什麼不用 CSS3DRenderer：iOS Safari `preserve-3d` 閃爍與文字模糊、pointer 不穩。
- 鏡頭過渡期間 overlay `opacity:0; inert`，tween 結束後 `layout()` 再顯示；連點無效。
- 紙雕立在書頁上半部，DOM 控制器（大 SVG 時鐘、選項卡）排在下半部與兩側——3D 與 DOM 在螢幕上**不重疊**，就沒有遮擋問題；容器本身 `pointer-events:none`，只有控制項開 `auto`。
- `?debug=1` 畫出投影角點 vs 容器外框並記錄最大誤差；M2 完成定義是**兩個方向轉向後誤差 < 2 px**。
- 時鐘的拖曳／吸附／時針分針連動／跨 12 點全部寫在純函式 `lib/clock-math.ts`（vitest 覆蓋），呈現層（SVG 控制器、3D 鐘面鏡射）只是它的兩個視圖——哪一層體驗不好都能換，邏輯不重寫。

### 音訊管線（可先跑、之後換好聲音只換腳本）
1. 台詞住書本 JSON 的 `lines`：`{ "p2.task.3": "把短針轉到 3，長針指著 12，就是 3 點！" }`；音檔 `public/audio/clock/<lineId>.mp3`，**一句一檔**（manifest 逐句記來源最自然、Howler 只解碼當頁需要的幾句、iOS 記憶體好控）。
2. `python3 tools/tts.py --book clock --backend azure|say [--only …] [--dry-run]`：hash = `sha256(backend|voice|params|text)`，manifest 同 hash 且檔案在就跳過。Azure 走 REST（`AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION` 環境變數，缺就明確報錯**不會**默默改用 say；REST 寫法借鏡 `profit/lib/tts_azure.py`，唯讀）；`say` 後端用 `-v Meijia` 出 aiff；兩者都經 ffmpeg `loudnorm` 轉 44.1 kHz mono 64 kbps mp3。
3. `manifest.json` 每句記 `hash、backend、voice、params、generatedAt、durationMs`；`check-audio` 比對，**台詞改了但音檔沒重產就紅；`--release` 模式下任何一句是 `say` 產的就紅**（擋佔位聲音上線）。
4. 執行期缺檔 → Web Speech API 頂上並在 console 記一筆（不做靜默降級）。
5. M5 第一件事：產 HsiaoChen 不同 pitch／rate 的三段樣本（同一句台詞）讓使用者用耳朵選，再全量產。

### 進度與人物
`localStorage['kidbooks.v1']`：`{ v: 1, active, profiles: [{ id, avatarId, name?, createdAt, books: { [bookId]: { pages: { [pageId]: { stars, attempts, completedAt } }, completedAt? } } }], settings: { sound } }`。版本欄位＋遷移函式 v1 就寫；storage 用參數注入（測試用 Map，不需 jsdom）；「書讀完」「裝飾解鎖」一律從頁面資料**推導**，不另存旗標（兩份會漂移）；每人最多 4 位。
- 人物頭像：**程式化紙偶**（4 款 SVG → 同一份圖既是選角畫面的頭像，也烤成貼圖貼在舞台裡有厚度的紙片上），不用 Kenney 角色包（頁面 404、風格也對不上）。
- **本機家長報告**（agent 審查補的，v1 就做、很小）：零追蹤意味著我們不知道小孩卡在哪，唯一合法的量測面是裝置內的資料——一頁 DOM 列每本書每頁的星數、嘗試次數、卡關頁，資料不離裝置；入口藏在 HUD 長按（小孩不會誤入）。

### 部署
- `wrangler.jsonc`：**assets-only Worker**（`assets.directory: ./dist`、`not_found_handling: single-page-application`、observability 關），`routes: [{ pattern: "books.lumenlilt.app", custom_domain: true }]`。獨立於 `runway/site` 的那個 Worker（一個 App 一個專案，同 evertend），**不要把 `books` 加進既有 lumenlilt Worker 的 routes**。
- `public/_headers`：CSP `default-src 'self'`（img/media 允許 data:/blob:）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`frame-ancestors 'none'`——兒童產品，零第三方連線是硬規則，`check-hosts` 掃 `dist/` 有外連就紅。
- `npm run deploy` ＝ `verify.sh`（typecheck → vitest → build → 四支 check）→ `wrangler deploy` → `check-site.sh books.lumenlilt.app`（沿 teamotif 的 deploy 鏈）。GitHub Actions 只跑 `verify`，部署留在本機（同其他專案）。
- 自訂網域：`custom_domain: true` 在同帳號 zone 下會自動建 DNS；若 token 權限不足，退而用 `~/.cloudflare/dns-token.txt`（dosekit 時期建的）或 dashboard——**這一步做完要 `dig` 驗證，不能信「沒噴錯」**。
- PWA：`manifest.webmanifest`（橫式、standalone、圖示）；service worker 只快取靜態資產，放 M6。

## 檢查（會紅的那種；每支做完都要**故意弄壞一次**證明它會紅）
- `tsc --noEmit`；`vitest`：clock-math（角度↔時間、吸附、連動跨 12）、書本狀態機表格（每個過渡態恰一個出口事件、reading 之外忽略輸入）、store 遷移、schema、跨參照（每個 `say` 都是 `lines` 的鍵；`activity.type` 集合＝註冊表鍵集合、`props[].type` ∈ 道具註冊表——**兩邊都推導，不寫死**）。
- `check-audio`：台詞↔音檔 hash；無孤兒音檔；`--release` 要求全部 azure。
- `check-assets`：從檔案系統列舉 `public/assets/`，每檔 ≥ 1 條 `LEDGER.json` 條目、每條目 ≥ 1 檔（不寫死檔名）；`CREDITS.md` 由 LEDGER 產生，不手寫。
- `check-font`：重算字集 hash 與字型 manifest 比對；`src/**` 不得含 CJK 字面值（缺字會靜默退回系統字型，所以只能靠檢查）。
- `check-hosts`：`dist/` 掃 `https?://` 外連，必須為零。
- `tools/check-site.sh`：部署後以 `<title>` 判斷（Cloudflare 對比不到的路徑回首頁 200，看狀態碼永遠綠）。
- 效能門檻寫進 README：iPad（A12 以上）Safari 60fps、draw calls < 120、首屏 < 3 MB。

## 風險與對策
- **iOS Safari WebGL 記憶體與效能**：pixelRatio 上限 2 且連續 2 秒平均幀 > 22 ms 自動降到 1.5；貼圖 ≤ 1024（書脊 256×1024）；一盞投影燈、陰影圖 iPad 1024²／桌機 2048²、`shadowMap.autoUpdate=false` 只在場景變動時更新；舞台道具用假陰影貼片；不做後製；三角面預算 < 100k；闔書即遞迴 `dispose`（M2 完成定義：開闔十次後 `renderer.info.memory` 回到基準）；`webglcontextlost` → 「休息一下」畫面＋重載（進度已持久化）。
- **音訊自動播放限制**：Howler 在第一次觸碰解鎖；選角畫面的第一次點擊就是解鎖點；`visibilitychange` 回前景 `ctx.resume()`。Web Audio **不受 iOS 靜音鍵影響**，README 要告訴家長。
- **DOM／WebGL 對位漂移**：單一 `layout()` 入口、讀 `visualViewport`、過渡期間 overlay 隱藏、debug 外框量誤差。
- **觸控拖拉被瀏覽器吃掉**：`touch-action: none`、阻止雙擊縮放與下拉更新、`100dvh`＋安全區。
- **CJK 字型太大**：子集化腳本掃實際用字；書脊用 canvas 貼圖同一字型。
- **Kenney GLB 格式**：官網沒列格式，下載後確認（2018 的家具包通常含 GLTF）；不行就 Blender 轉。
- **Azure 聲音太平**：先用 Speech Studio 試聽；不夠再比 ElevenLabs——只換 `tts.py` 後端，App 不動。
- **色彩管理**：three 0.186 預設 sRGB 輸出與 ColorManagement 開啟；貼圖標 `colorSpace = SRGBColorSpace`；`toneMapping = NoToneMapping`（ACES 會把粉彩壓灰）；色板集中一檔（M1 切換色調就是換它）。
- **「資料驅動」只有一半是真的**（agent 審查點）：第一本書就要 6 種活動元件＋5 種道具，JSON 是薄薄一層蓋在程式碼上，第二本書幾乎一定要新增元件。對策不是現在把 schema 做得很通用，而是把 `activities/`、`props/` 明確定位為**外掛資料夾＋穩定契約**（元件只透過 `ctx` 拿資源、不 import 引擎內部），等規劃第二本書時量「多少頁能用既有元件表達」再決定抽象。
- **貓不夠可愛**：程式幾何先做（球＋圓角盒、平面著色）；不行就 Blender 5.2 的 bpy 腳本建模輸出 GLB（腳本進 repo，模型可重生）。貓是 M1 就要給使用者看的東西，早失敗早換路。
- **貓的工量**：狀態機五態＋跳躍路徑，是 v1 最容易膨脹的項目；M2 先做 idle＋跳到書角兩態，cheer 與 talk 放 M4／M5。

## 對抗審查結果（規劃 agent，2026-09-12）
它挑的三個最弱點與處置：
1. **兩套命中系統疊在一起**（3D raycast 拖指針 vs DOM 按鈕）最容易出怪 bug → 本計畫本來就把拖曳放在 DOM 的 SVG 時鐘，再採納它的建議把邏輯抽成純函式層，呈現層可換。
2. **資料驅動只有一半是真的** → 採納：外掛資料夾＋穩定契約，第二本書再量要不要抽象（見風險）。
3. **教學有效性沒有回饋迴路** → 採納：本機家長報告進 v1（見進度與人物）。
其他採納：對位改「每次 layout 投影一次」、`visualViewport`、程式化紙偶取代 Kenney 角色、四支檢查器、CSP 與零外連、釘大版套件、Azure 金鑰重用。未採納：它把可拖的時鐘做成 3D 道具（理由同第 1 點）。
